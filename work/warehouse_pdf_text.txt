基于多级优先级队列的智能仓库任务调度仿真系
统
⼀、实验项⽬名称
基于  LINKBOY 平台的多级优先级队列智能仓库任务调度仿真系统
⼆、实验⽬的
1. 理解任务调度算法在物流仓储系统中的应⽤价值，掌握优先级调度、时间⽚轮转、最短作业
优先等调度策略。
2. 熟悉  LINKBOY 仿真平台中控制器、屏幕、矩阵键盘、⽆线遥控器、点阵屏、串⼝、灯带、舵
机、四按钮、计时器等硬件的使⽤⽅法。
3. 掌握多级队列、优先队列（堆）、任务控制块等数据结构在任务调度系统中的应⽤。
4. 提⾼分析不同调度算法对系统吞吐量、平均等待时间、任务截⽌时间满⾜率等性能指标影响
的能⼒。
三、系统需求分析
3.1 功能需求
1. 多优先级任务⽣成功能
系统模拟三种类型的仓库任务：紧急订单（优先级最⾼）、普通补货（优先级中等）、低优先
级巡检（优先级最低）。
每种任务的到达间隔服从不同分布：紧急订单每  815 秒到达⼀个，普通补货每  38 秒到达⼀
个，低优先级巡检每  10~20 秒到达⼀个。
每个任务包含：任务 ID 、任务类型、优先级（ 1/2/3 ， 1 最⾼）、预计执⾏时⻓（ 2~6 秒）、到
达时间戳。
2. 多级优先级队列调度功能
创建三个独⽴的队列，分别存放⾼、中、低优先级任务。
调度器按以下规则选择下⼀个执⾏的任务：
严格优先级（⾮抢占式）：只要⾼优先级队列⾮空，总是执⾏⾼优先级任务；否则执⾏中
优先级，最后低优先级。
加权轮询（可选模式）：可通遥控器切换为 “ 加权轮询模式 ” ，⾼ / 中 / 低队列分配  5:3:2 的
时间⽚⽐例。
每次调度时，从选中的队列中取出队⾸任务执⾏。
3. 任务执⾏与资源占⽤模拟
使⽤舵机模拟任务执⾏机构：舵机转动到指定⻆度并保持⼀段时间表⽰ “ 执⾏任务 ” ，转动⻆
度⼤⼩与任务类型关联（紧急订单  → 180° ，普通补货  → 90° ，低优先级巡检  → 0° ）。
使⽤灯带颜⾊表⽰当前执⾏任务的优先级：红⾊ = ⾼优先级，⻩⾊ = 中优先级，绿⾊ = 低优先
级。
使⽤屏幕实时显⽰当前执⾏的任务 ID 、队列⻓度（三个队列）、调度模式、系统吞吐量等。
4. 调度策略切换与⼿动⼲预
⽆线遥控器（ 4 键）：
A 键：切换调度模式（严格优先级  ↔ 加权轮询）。
B 键：紧急暂停（当前任务执⾏完后停⽌新任务调度）。
C 键：恢复调度。
D 键：⼿动强制插⼊⼀个紧急订单（⽴即⼊⾼优先级队列）。
四按钮独⽴按键：
按钮 1 ：记录并显⽰当前三个队列的任务快照（ ID 、等待时间）。
按钮 2 ：清空所有任务队列（紧急情况复位）。
按钮 3 ：切换屏幕显⽰模式（显⽰实时性能指标  vs 显⽰队列详情）。
按钮 4 ：发送当前系统性能统计报告到串⼝。
5. 矩阵键盘配置功能
通过矩阵键盘动态修改调度参数：
数字键  + A ：修改⾼优先级队列的最⼤⻓度（默认 10 ）。
数字键  + B ：修改中优先级队列最⼤⻓度（默认 15 ）。
数字键  + C ：修改低优先级队列最⼤⻓度（默认 20 ）。
* 键：重置所有队列⻓度为默认值。
# 键：显⽰当前调度参数。
6. 数据统计与性能分析功能
系统⾃动记录以下指标（存储在列表中）：
每个任务的等待时间（从⼊队到开始执⾏的时间差）。
每个任务的周转时间（从⼊队到执⾏完成的时间差）。
任务完成数量（按优先级分别统计）。
任务丢弃数量（队列满时⽆法⼊队的任务）。
每分钟⾃动计算⼀次平均等待时间、平均周转时间，并通过串⼝发送。
7. 串⼝通信与监控功能
上⾏数据（系统  → 上位机）：
实时发送每个任务开始执⾏和完成的信息（任务 ID 、类型、等待时间）。
每分钟发送性能统计报告（平均等待时间、吞吐量）。
队列溢出时发送报警信息。
下⾏命令（上位机  → 系统）：
"STAT" ：⽴即返回当前统计摘要。
"CLEAR" ：清空所有统计记录。
"MODE <0/1>" ：设置调度模式（ 0= 严格优先级， 1= 加权轮询）。
"ADD <type>" ：⼿动添加⼀个指定类型的任务（ type=1/2/3 ）。
3.2 性能需求
任务调度响应时间  ≤ 200ms （从队列有任务到舵机开始动作）。
系统⽀持⾄少 3 个优先级队列，每个队列最⼤容量可配置（默认⾼ 10 、中 15 、低 20 ）。
任务到达间隔随机，模拟真实物流的不确定性。
系统连续仿真运⾏  ≥ 30 分钟⽆死锁或异常。
串⼝通信波特率  115200bps ，数据格式  JSON 或  CSV 。
3.3 ⽤⼾⻆⾊与约束
调度员：通过遥控器、按钮、键盘实时调整调度策略和参数。
管理员：通过串⼝上位机远程监控系统性能，分析调度算法效果。
约束：所有硬件基于  LINKBOY 平台仿真，采⽤图形化积⽊编程。

五、数据结构设计（图形化描述）
5.1 任务控制块（ Task Control Block ）
每个任务⽤⼀组变量表⽰，在  LINKBOY 中通过列表（ List ）存储多个任务。每个任务包含以下属
性（存储在同⼀个列表的不同索引或分列表存储）：
字段名 数据类型 说明
taskID 整数 任务唯⼀编号，从 1 开始递增
type 整数（ 1~3 ） 1= 紧急订单， 2= 普通补货， 3= 巡检
priority 整数（ 1~3 ） 1最⾼， 3 最低（与 type 相同）
execDuration整数（毫秒）预计执⾏时⻓（ 2000~6000ms ）
arriveTime 整数 系统运⾏毫秒数（⼊队时刻）
startTime 整数 开始执⾏时刻（初始 0 ）
finishTime 整数 完成时刻（初始 0 ）
在  LINKBOY 中，可以创建  7个列表（每个属性⼀个列表），每个任务的相同索引位置对应同⼀任
务；或者创建⼀个任务列表，每个元素是 “ 任务 ID” ，其他属性通过单独的映射表存储。推荐前
者，⽅便图形化操作。
5.2 多级队列结构
创建三个队列，每个队列⽤列表模拟，配合队⾸ / 队尾指针。由于  LINKBOY 列表操作⽅便，可以
直接使⽤ “ 列表末尾添加 ” 表⽰⼊队， “ 删除列表第⼀项 ” 表⽰出队，但为了模拟固定容量和性能，建
议⼿动管理指针。
⾼优先级队列（ Q_High ）：
列表  queueHigh  存储任务 ID （或完整任务副本）。
变量  highHead , highTail , highCount , highMaxLen 。
中优先级队列（ Q_Mid ）：
列表  queueMid ，指针变量类似。
低优先级队列（ Q_Low ）：
列表  queueLow ，指针变量类似。
队列基本操作伪代码：
⼦程序  ⼊队 ( 队列名 , 任务 ID):
  如果  队列名 .count < 队列名 .maxLen:
    将  任务 ID 添加到  队列名 .list 的末尾   // 简化操作，直接使⽤列表追加
    队列名 .count += 1
    返回  真
  否则 :
    串⼝发送  " 队列满，丢弃任务  ID: " + 任务 ID
    丢弃计数  += 1
    返回  假
⼦程序  出队 ( 队列名 ):
  如果  队列名 .count > 0:
    任务 ID = 队列名 .list[0]  // 获取队⾸
    删除  队列名 .list[0]
    队列名 .count -= 1
    返回  任务 ID
  否则 :
    返回  -1
5.3 统计信息存储
历史任务记录列表：每个已完成任务存储⼀条字符串或分列表存储。记录格式：
任务 ID 、类型、等待时间（ ms ）、周转时间（ ms ）、是否被丢弃。
由于列表⻓度有限，可设定最多保留最近  100 条记录。
性能指标变量：
totalTasksHigh , totalTasksMid , totalTasksLow ：各优先级已完成任务数。
sumWaitTimeHigh , sumWaitTimeMid , sumWaitTimeLow ：各优先级总等待时间（⽤于计算平均
值）。
totalDiscarded ：总丢弃任务数。
lastReportTime ：上次发送性能报告的时刻（毫秒）。
5.4 随机数⽣成
任务到达间隔：每种优先级独⽴计时器，使⽤  random()  ⽣成间隔毫秒数。
任务执⾏时⻓：random(2000, 6000)  毫秒。
随机种⼦在系统启动时固定（如  randomSeed(1234) ），保证实验可重现。
5.5 调度模式与状态变量
schedMode ： 0 = 严格优先级（⾮抢占）， 1 = 加权轮询。
systemState ： 0 = 运⾏， 1 = 暂停（暂停新任务调度，当前任务可完成）。
rrCounter ：加权轮询模式下的时间⽚计数器（仅⽰意，实际可⽤定时器）。
currentTaskID ：当前正在执⾏的任务 ID （若⽆则为 -1 ）。
currentTaskRemainingTime ：当前任务剩余执⾏时间（毫秒）。
六、软件过程设计
6.1 主程序流程（⽆限循环）
系统启动后执⾏⼀次：
1. 初始化所有硬件模块（屏幕、串⼝、灯带、舵机归中）。
2. 初始化三个队列（清空列表，设置最⼤⻓度默认值）。
3. 初始化统计变量归零。
4. 设置随机种⼦（固定值  1234 ）。
5. 设置系统状态为 “ 运⾏ ” ，调度模式为 “ 严格优先级 ” 。
6. 设置三个优先级任务的 “ 上次到达时间 ” 和 “ 下次间隔 ” 变量。
7. 在屏幕上显⽰ “ 系统就绪 ” 。
然后重复执⾏以下步骤（永不停⽌）：
步骤 1 ：任务到达⽣成（独⽴计时器，每个优先级独⽴）
对于  priority = 1,2,3 ：  如果  系统状态  == 运⾏ : 当前时间  = 运⾏毫秒数  如果  当前时间  - 上次到达
时间 [priority] ≥ 下次间隔 [priority]: 任务 ID ⾃增 1 创建任务对象（ ID, type=priority, priority,
execDuration= 随机 (2000,6000), arriveTime= 当前时间）  根据优先级调⽤对应的⼊队操作  如果⼊
队成功：  在屏幕更新该队列⻓度显⽰  串⼝发送  " 任务到达 : ID=X, 类型 =Y" 否则：  串⼝发送  " 队列
满，丢弃任务  ID=X" 灯带橙⾊闪烁 0.2 秒  更新上次到达时间为当前时间  ⽣成新的随机间隔（毫
秒）：  ⾼优先级： random(8000,15000) 中优先级： random(3000,8000) 低优先级：
random(10000,20000)
步骤 2 ：调度与任务执⾏
如果  系统状态  == 运⾏  且  当前没有正在执⾏的任务（ currentTaskID == -1 ） : 选择下⼀个任务
（根据  schedMode ）：  若  schedMode == 0 （严格优先级）：  如果  ⾼优先级队列⾮空 : 任务  = 出
队 ( ⾼ ) 否则如果  中优先级队列⾮空 : 任务  = 出队 ( 中 ) 否则如果  低优先级队列⾮空 : 任务  = 出队 ( 低 )
否则 : ⽆任务，跳过  若  schedMode == 1 （加权轮询）：  // 简化实现：每轮依次检查三个队列，但
给⾼优先级更多机会  // 具体可采⽤时间⽚⽐例：⾼队列每次最多取 3 个，中队列 2 个，低队列 1
个，循环  实现⼀个简单的轮询指针，按⽐例分配  如果有任务 : currentTaskID = 任务 .ID
currentTaskStartTime = 当前时间  记录任务的开始时间到任务属性中  根据任务类型设置舵机⽬标
⻆度（ 1→180° ， 2→90° ， 3→0° ）  控制舵机转动  设置灯带颜⾊（红 / ⻩ / 绿）  设置⼀个定时器
（ currentTaskRemainingTime = 任务的预计执⾏时⻓）  屏幕显⽰ " 执⾏任务  ID: X"
步骤 3 ：任务执⾏完成检查
如果  currentTaskID != -1: 当前时间  = 运⾏毫秒数  如果  当前时间  - currentTaskStartTime ≥
currentTaskRemainingTime: 任务完成  记录完成时间，计算等待时间（ startTime - arriveTime ）和
周转时间（ finishTime - arriveTime ）  更新统计变量（增加计数和总等待时间）  将任务记录存⼊历
史列表  串⼝发送  " 任务完成 : ID=X, 等待时间 =Y ms, 周转时间 =Z ms" 舵机归中（转到 90° ）  灯带
恢复默认（绿⾊常亮表⽰空闲）  currentTaskID = -1
步骤 4 ：遥控器信号处理
检查⽆线遥控器接收标志：  A 键：切换  schedMode （ 0↔1 ），屏幕显⽰当前模式，串⼝发送模式
切换信息。  B 键： systemState = 1 （暂停），停⽌新任务调度（当前任务继续完成）。  C 键：
systemState = 0 （恢复），并清除暂停标志。  D 键：⽴即⽣成⼀个⾼优先级任务（紧急订单），强
制⼊队⾼优先级队列，忽略原到达间隔。
步骤 5 ：四按钮独⽴按键处理
按钮 1 ：调⽤⼦程序 “ 显⽰队列快照 ” （在屏幕上滚动显⽰各队列前 5 个任务的 ID 和等待时间）。  按钮
2 ：清空所有任务队列（清除列表，重置队⾸队尾，同时如果有正在执⾏的任务则让它完成但不从
队列取新任务）。  按钮 3 ：切换屏幕显⽰模式（模式 A ：实时性能指标；模式 B ：队列详情）。  按钮
4 ：调⽤⼦程序 “ 发送性能报告 ” 到串⼝（当前平均等待时间、已完成任务数、丢弃数）。
步骤 6 ：矩阵键盘扫描
如果有键盘按键：  读取按键组合（如数字 + 字⺟）  根据预设命令修改队列最⼤⻓度或调度参数  屏
幕提⽰修改⽣效
步骤 7 ：串⼝接收处理
如果串⼝有数据：  读取⼀⾏命令（以换⾏结束）  解析命令：  "STAT" → ⽴即发送统计摘要（ JSON
格式）  "CLEAR" → 清空所有历史统计记录，重置计数器  "MODE 0" → 设置  schedMode = 0
"MODE 1" → 设置  schedMode = 1 "ADD 1" → ⼿动⽣成⼀个⾼优先级任务并⼊队  "ADD 2" → ⼿
动⽣成⼀个中优先级任务  "ADD 3" → ⼿动⽣成⼀个低优先级任务  "GETQ" → 发送三个队列的当前
⻓度
步骤 8 ：周期性性能报告（每分钟）
如果当前时间  - lastReportTime ≥ 60000 毫秒：  调⽤⼦程序 “ 发送性能报告 ” （同按钮 4 ）
lastReportTime = 当前时间
步骤 9 ：屏幕刷新
每隔  200ms 刷新⼀次屏幕显⽰（避免闪烁）：  显⽰当前调度模式、系统状态。  显⽰三个队列⻓
度。  显⽰当前执⾏的任务 ID 及剩余时间。  若在性能显⽰模式，显⽰平均等待时间和吞吐量。  若
在队列详情模式，显⽰各队列队⾸任务信息。
步骤 10 ：循环延时
每次循环结束延时  10 毫秒，保持响应性。
6.2 各⼦模块详细伪代码
6.2.1 ⼊队⼦程序（图形化实现参考）
⼦程序  ⼊队 ( 队列类型 , 任务对象 ):
  变量  队列列表  = 根据类型选择 (queueHigh, queueMid, queueLow)
  变量  最⼤⻓度  = 根据类型选择 (highMaxLen, midMaxLen, lowMaxLen)
  变量  当前⻓度  = 列表⻓度 ( 队列列表 )
  如果  当前⻓度  < 最⼤⻓度 :
    将  任务对象  添加到  队列列表  末尾
    返回  真
  否则 :
    串⼝发送  " 队列满，丢弃 " + 任务对象 .ID
    全局丢弃计数  += 1
    返回  假
6.2.2 出队⼦程序
⼦程序  出队 ( 队列类型 ):
  变量  队列列表  = 根据类型选择
  如果  列表⻓度 ( 队列列表 ) > 0:
    变量  任务  = 队列列表 [0]
    删除  队列列表 [0]  // 移除第⼀项
    返回  任务
  否则 :
    返回  空
6.2.3 严格优先级调度选择
⼦程序  选择任务 _ 严格优先级 ():
  任务  = 空
  如果  列表⻓度 (queueHigh) > 0:
    任务  = 出队 ( ⾼ )
  否则如果  列表⻓度 (queueMid) > 0:
    任务  = 出队 ( 中 )
  否则如果  列表⻓度 (queueLow) > 0:
    任务  = 出队 ( 低 )
  返回  任务
6.2.4 加权轮询调度选择（简化版）
变量  轮询计数器  = 0  // 全局变量，每调度⼀次递增
⼦程序  选择任务 _ 加权轮询 ():
  任务  = 空
  轮询计数器  = ( 轮询计数器  + 1) % 6  // 6 次⼀个周期
  // ⽐例：⾼ : 中 : 低  = 3:2:1
  如果  轮询计数器  < 3 且  列表⻓度 (queueHigh) > 0:
    任务  = 出队 ( ⾼ )
  否则如果  轮询计数器  < 5 且  列表⻓度 (queueMid) > 0:
    任务  = 出队 ( 中 )
  否则如果  列表⻓度 (queueLow) > 0:
    任务  = 出队 ( 低 )
  否则 :
    // 如果对应队列空，则尝试其他⾮空队列
    如果  列表⻓度 (queueHigh) > 0: 任务  = 出队 ( ⾼ )
    否则如果  列表⻓度 (queueMid) > 0: 任务  = 出队 ( 中 )
    否则如果  列表⻓度 (queueLow) > 0: 任务  = 出队 ( 低 )
  返回  任务
6.2.5 统计报告⽣成
⼦程序  发送性能报告 ():
  计算平均等待时间（⾼ / 中 / 低分别）：
    如果  totalTasksHigh > 0: avgWaitHigh = sumWaitTimeHigh / totalTasksHigh
    否则  avgWaitHigh = 0
    同理中、低
  总体平均等待时间  = (sumWaitTimeHigh+sumWaitTimeMid+sumWaitTimeLow) /
(totalTasksHigh+totalTasksMid+totalTasksLow)
  吞吐量  = (totalTasksHigh+totalTasksMid+totalTasksLow) / ( 运⾏分钟数 )
  组装字符串：
    "=== Performance Report ==="
    "High: tasks=XX, avgWait=XX ms"
    "Mid: tasks=XX, avgWait=XX ms"
    "Low: tasks=XX, avgWait=XX ms"
    "Overall avgWait=XX ms, Throughput=XX tasks/min"
    "Discarded=XX"
  通过串⼝发送
