# 本次 LinkBoy 实现经验

## 1. 先学习本地 `.lab` 素材

用户提供的 `资产/` 目录中有 20 个分解版 `.lab`，这些文件比凭空拼模块更可靠。实现总工程前应先扫描它们的组件路径、事件块、函数块、循环块和连线格式，再把可用范式合并到目标工程。

本次吸收的关键素材包括：

- 无线遥控器和接收器：`2.lab`
- 点阵显示：`3.lab`、`4.lab`、`7.lab`
- 串口通信：`5.lab`、`weweek6-20.20.lab`
- 湿度采集：`6.lab`
- LCD、信息显示器、矩阵键盘：`weweek6-1.20.lab`、`weweek6-11.20.lab`
- HX711 称重：`weweek6-10.20.lab`
- 舵机：`weweek6-12.20.lab`、`weweek6-13.20.lab`
- PPM：`weweek6-8.20.lab`
- 灯带：`weweek6-9.20.lab`
- 四按钮：`weweek6-18.20.lab`、`weweek6-19.20.lab`

## 2. `.lab` 要同时满足代码区和图形区

LinkBoy 打开工程时不仅看代码，还看 `//[图形界面]` 后面的组件、链接和积木元数据。只写代码区会导致用户看不到“图片里的东西”，也会出现模块不完善、连线缺失、无值函数空壳等问题。

本次最终工程同时补齐：

- GUI 组件块
- 硬件连线 `//[链接]`
- `UserFunctionIns` 无值函数
- `FuncIns` 子积木
- `ForeverIns`
- `LoopIns`
- `IfElseIns` / `ElseIns`

## 3. LinkBoy 会自动保存并改写 `.lab`

仿真时 LinkBoy 可能自动保存工程，并把源码段或部分元数据改写掉。因此验证时不要直接跑正式 `work/port_sort.lab`，应先复制临时副本，例如：

```powershell
Copy-Item D:\linkboy\work\port_sort.lab D:\linkboy\work\port_sort_window_verify.lab -Force
```

正式文件只由生成脚本和人工确认后的步骤更新。

## 4. 路径、编码和版本字段很关键

本次稳定做法：

- 使用 `D:\linkboy\work\port_sort.lab` 这种英文短路径，避免 LinkBoy 最近路径或中文路径触发非法字符问题。
- `.lab` 用 GBK 写入，贴合 LinkBoy 官方示例。
- 工作台版本字段对齐本机 LinkBoy `5.56.250511`。
- 组件路径尽量来自本机官方示例和用户素材，不凭空猜。

## 5. PDF 章节存在冲突时要记录取舍

PDF 3.2 写队列满时丢弃最旧任务，但 5.2 和 6.2.2 更具体地写为丢弃新任务。本工程按数据结构设计和伪代码章节执行：队列满时丢弃新任务并报警。

无线遥控也类似：部分章节提到紧急停止，6.1 主流程给出 A/B/C/D 具体映射。本工程按 6.1 做 A 启动、B 暂停、C 复位、D 灯带测试；紧急停止保留在串口 `E` 和矩阵键盘 10。

## 6. LCD 空白问题的处理

不能只依赖隐藏源码段驱动 LCD。需要在图形化无值函数中放入真实 `信息显示器` 子积木，让 LinkBoy 打开和仿真时都能看到显示逻辑。

最终显示内容包括：

- `H:` 湿度
- `Q:` 队列长度
- `S:RUN` / 状态
- `W:` 最近重量
- `L:` 轻货阈值

初始化时还需要打开 LCD 背光并设置初始变量。

## 7. 仿真验证只用窗口级截图

本次将探针从 `Screen.PrimaryScreen + CopyFromScreen` 改为 `Application.OpenForms + DrawToBitmap`，只捕获：

- `v_GForm.GForm`
- `n_SimForm.SimForm`

日志使用 `WINDOW_SCREEN=`，不再输出旧的 `SCREEN=`。这是以后本地 GUI/仿真取证的默认做法。

## 8. 可复现验收信号

本次最有用的验收信号：

- `python tools\check_port_sort_requirements.py`

## 9. 智能仓库项目补充：图形块必须只调用图形可见函数

第二个项目“基于多级优先级队列的智能仓库任务调度仿真系统”暴露了一个关键坑：LinkBoy 图形区的 `@USER` 调用只能引用已经在图形区声明出来的可见无值函数。不能在图形积木里直接写：

```text
?void @USER 任务到达生成
```

即使代码区里真的存在 `void 任务到达生成()`，LinkBoy 仿真时仍可能报：

```text
<函数调用> 未定义的函数或函数指针：#1.任务到达生成
```

稳定做法：

- 图形区主流程只调用 `可视化初始化系统`、`可视化任务到达生成`、`可视化严格优先级调度` 这类已经生成 `UserFunctionIns` 的可见函数。
- 具体业务函数可以保留在代码区，但图形区不要用 `@USER` 直接跨过去调用隐藏函数。
- 如果某个步骤必须在图形区可见，就用 LinkBoy 官方格式积木表达，例如变量赋值、串口发送、舵机角度、灯带颜色、LCD 显示等。
- 每次生成后用测试扫描 `.lab`，禁止出现隐藏函数调用，例如 `?void @USER 任务到达生成`。

## 10. 仿真时间源不要依赖软件计时器读数

智能仓库项目里 LCD 数字不变的主要风险来自时间源。LinkBoy 仿真中 `计时器.计时时间` 可能不按预期递增，屏幕刷新和任务到达都会看起来卡住。

稳定做法是在主循环中本地推进仿真时间：

```text
当前时间 = 当前时间 + 10s;
延时器.延时_毫秒((10s));
```

同时在 LCD 第一行显示 `T:` 和 `当前时间`，方便肉眼确认仿真确实在推进。测试里要同时锁住：

- 必须存在 `当前时间 = 当前时间 + 10s;`
- 必须存在 LCD `T:` 和 `当前时间` 显示块
- 禁止退回 `当前时间 = 计时器.计时时间;`
- 禁止任何图形块把 `当前时间` 重置为 0

## 11. LinkBoy 打开或仿真后可能改写正式 `.lab`

智能仓库项目中出现过正式文件被 LinkBoy 打开后改写，导致代码区检查临时失败。以后不要把“打开后的文件内容”当成唯一事实来源。

稳定流程：

1. 正式成果只由生成脚本输出。
2. 仿真前复制临时副本，例如 `warehouse_scheduler_runtime_verify.lab`。
3. 探针只跑临时副本，验证结束删除临时副本和窗口截图。
4. 如果用户窗口里还停着旧工程，重新打开正式 `.lab`，必要时提示旧窗口可能是缓存状态。

## 12. LCD/OLED 等价实现要把显示积木放进图形区

用户允许用 `LCD/2004 + 信息显示器` 等价实现 OLED 128x64，但不能只在源码区写显示函数。否则用户会看不到“图片里的东西”，或者仿真时屏幕空白。

稳定做法：

- 组件区必须有 `Arduino\lcd2004PCF8574\Pack.B` 和 `信息显示器`。
- 初始化要打开 LCD 背光。
- 可视化函数里要有真实 `信息显示器 清空`、`在第...行第...列显示信息`、`向后显示数字` 积木。
- 显示文本要短，适合 20x4：例如 `ID:`、`T:`、`Q:`、`Done:`、`WRR 3:2:1`。
- 每 200ms 刷新屏幕，主循环 10ms 延时，避免刷屏过快。

## 13. 以后做 LinkBoy 项目的硬检查清单

新项目交付前至少过这些检查：

- 文件是 GBK/GB18030 兼容编码，LinkBoy 打开不乱码。
- 代码区存在 `void main0()`、`OS_VarInit()`、主循环和必要用户函数。
- 图形区存在组件、连线、`UserFunctionIns`、`FuncIns`、`ForeverIns`、`IfElseIns`、`ElseIns`。
- 可见无值函数不能是空壳，不能只靠代码模式。
- 图形区 `@USER` 调用必须全部能在图形区找到对应 `UserFunctionIns`。
- 不允许图形区调用隐藏代码函数。
- 不允许图形区把运行时变量反复清零，例如 `当前时间 = 0`。
- 主循环必须有明确时间推进和末尾短延时。
- LCD/串口/舵机/灯带等用户可见输出必须在图形块里有对应积木。
- 仿真验证必须使用临时副本和窗口级截图，日志中应有 `WINDOW_SCREEN=`，不应有全屏 `SCREEN=`。
- TDD 审计脚本必须覆盖 PDF 流程条目，不能漏掉 6.1 的 10 个循环步骤。
- 最终打开给用户看时，确认新窗口标题指向正式 `.lab`，避免旧窗口缓存误导。
